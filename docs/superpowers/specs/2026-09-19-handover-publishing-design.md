# 交接发布自动化设计

## 目标

让当前交接文档成为项目维护入口。每次更新指定交接文档后，维护者执行一次明确的发布命令，命令自动刷新 README 顶部的置顶交接区，检查敏感内容，只提交 README 和交接文档，并推送到 GitHub 私有仓库的 `main` 分支。

## 已确认的约束

- 项目唯一工作区为 `F:\媒体监测`。
- GitHub 目标为 `c2586081610-sys/social-monitor-workbench` 的 `main` 分支。
- 当前交接文档为 `docs/项目交接文档_2026-09-19_实测版.md`。
- “实时更新”指每次交接文档更新时同步发布，不是监控进程定时写数据库状态并推送。
- 运行配置、数据库、cookie、媒体、Obsidian 与其他未提交开发修改不得被该发布流程加入提交。

## 范围

新增一个项目内发布工具，例如 `tools/publish_handover.py`，并在 README 标题后维护一个机器可定位的置顶区：

```markdown
<!-- HANDOVER_PIN:START -->
> **当前项目交接**：[项目交接文档](docs/项目交接文档_2026-09-19_实测版.md)
>
> 唯一活动项目目录：`F:\媒体监测`。交接文档更新后，使用交接发布工具同步 README 并推送 GitHub `main`。
>
> 最近发布：YYYY-MM-DD HH:MM Asia/Shanghai
<!-- HANDOVER_PIN:END -->
```

置顶区只承担导航、项目目录和最近发布日期职责。完整架构、数据快照、运行方式和风险只保留在交接文档，避免 README 与交接文档出现两套会漂移的状态说明。

## 发布流程

1. 维护者编辑交接文档。
2. 执行 `python tools/publish_handover.py --publish`。
3. 工具验证指定交接文档存在，更新或插入 README 的唯一置顶区，并使用上海时区写入发布日期。
4. 工具扫描两个待发布文档，拒绝出现常见凭据形式，例如 B 站会话字段、Bearer 值、密码赋值或访问令牌赋值。
5. 工具执行 `git diff --check`，只使用显式路径暂存 `README.md` 与该交接文档；不使用 `git add .`。
6. 若这两个文件没有变化，工具退出且不创建空提交。
7. 工具创建 `docs(handover): publish current handover` 提交，并执行 `git push origin HEAD:main`。
8. 推送成功后输出提交短哈希、远端分支和交接文档路径；失败时保留本地提交并给出可重试提示，不回滚或改写任何其他工作。

## 命令模式

- `python tools/publish_handover.py --dry-run`：只显示将更新的 README 区块和将提交的文件，不写文件、不暂存、不提交、不推送。
- `python tools/publish_handover.py --publish`：执行受控发布。
- 文档路径可作为显式参数覆盖默认值，但必须位于项目 `docs` 目录内，且扩展名为 `.md`。

默认模式为 `--dry-run`，避免误执行网络写操作。后续由 Codex 在完成交接文档更新时运行 `--publish`，或由维护者手动执行该命令。

## 安全边界

- 只暂存 README 和一个明确的 `docs/*.md` 交接文件。
- 任意其他已修改、删除或未跟踪文件均不暂存、不提交、不推送。
- 不读取、不输出、不上传 `config`、数据库、媒体、浏览器 profile、Obsidian 或 WorkBuddy 运行文件。
- 发现敏感字面量、Git 未安装、GitHub 身份不可用、非 Git 仓库或目标文档不在 `docs` 时立即失败。
- 本机已有的其他工作树修改不是发布阻塞条件；它们会被保留在原状。

## 测试策略

使用临时 Git 仓库测试以下情形：

1. README 没有置顶区时能够在标题后插入一个区块。
2. README 已有置顶区时只替换该区块，不重复插入。
3. 干跑不改文件、不创建提交。
4. 发布只暂存 README 与目标交接文档，保留一个额外的未跟踪文件。
5. 出现敏感字段时拒绝发布。
6. 空变更时不提交。
7. 推送命令为 `origin HEAD:main`，并对推送失败返回非零退出码及可读错误。

## 非目标

- 不建立文件监听器、计划任务或自动后台推送。
- 不将数据库、轮询日志、实时运行状态写入 GitHub。
- 不清理、合并或提交当前工作树中既有的其他修改。
- 不改变监控、下载、转写、AI 笔记或平台抓取行为。

## 验收标准

- README 顶部始终有一个、且仅有一个交接置顶区，链接到指定交接文档。
- `--dry-run` 无文件和 Git 状态写入。
- `--publish` 的提交文件清单严格限于 README 与目标文档。
- 包含典型凭据的交接文档无法发布。
- 成功发布后 GitHub `main` 能看到 README 置顶区和更新后的交接文档。
